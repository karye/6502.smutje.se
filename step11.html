Städad adressrymd

Mål

I steg 10 fick vi en fristående dator — men adressrymden var inte vacker. VIA:ns 16 bytes på $4000 klippte av SRAM-minnet mitt i, och den övre halvan av 62256-chippet ($4000–$7FFF) låg helt oanvänd. Det kändes slarvigt.

Nu städar vi upp. SRAM utökas till hela 32 KB ($0000–$7FFF) genom att ansluta A14 — hela 62256-chippet används äntligen. VIA:n flyttas till $A000–$A00F, ett rent I/O-fönster i ROM:ens övre del, precis som I/O-portar sitter på riktiga 6502-datorer (Apple II hade I/O på $C000, C64 på $D000).

Resultatet är en adressrymd utan dött utrymme: RAM längst ner, ROM i mitten och I/O i ett fönster högst upp. Det här är den klassiska 6502-layouten — nu har vi byggt den själva.

Nya komponenter

Inga nya kretsar! Det här steget handlar om att omkoppla det vi redan har. Du behöver bara en andra 74HC00 för den nya adressavkodningen (du har sex stycken) och en extra kopplingstråd för SRAM:ns A14.

Kopplingsschema

Schemat visar den städade bussen: SRAM täcker nu hela nedre halvan, VIA sitter i ett fönster på $A000, och EEPROM täcker $8000–$FFFF med ett 16-byte-hål där VIA:n bor.

Schema kommer snart — se avkodningstabellerna nedan så länge.

Adressavkodning

Allt handlar om vilken enhet som får prata på bussen. Tre enheter, tre chip select-signaler — och nu med två 74HC00-chips räcker grindarna till.

Gamla kartan (steg 10) — problemen

✗ SRAM bara 16 KB: 62256 är ett 32 KB-chip, men A14 var inte ansluten. Den övre halvan låg död.

✗ VIA klippte av minnet: 16 bytes på $4000 mitt i adressrymden delade RAM:et i två — $0000–$3FFF använt, $4000–$7FFF dött.

✗ EEPROM-avkodning enkel: bara NOT A15 — fungerade, men kunde inte samexistera med VIA på samma sida.

Nya kartan (steg 11)

✓ SRAM 32 KB ($0000–$7FFF): A14 ansluts, /CE = NOT A15 — hela chippet aktivt när A15=0.

✓ VIA på $A000–$A00F: /CS2 = A15·¬A14·A13·¬A12 — bara 16 bytes, inget mer.

✓ EEPROM på $8000–$FFFF: /CE = A15·¬(VIA) — aktivt överallt utom just VIA-fönstret.

74HC00 #2 — nya grindar

Den andra 74HC00:an (låt oss kalla den U5) sköter den nya avkodningen. Fyra grindar, fyra signaler:

Logik i ord: VIA får prata när A15=1 (övre halvan), A14=0, A13=1 och A12=0 — det vill säga exakt $A000–$A00F. EEPROM:et får prata när A15=1 och VIA inte gör det. SRAM får prata när A15=0. Ingen krock, inget dött utrymme.

Arduino-kod

Ändringarna i Arduinon är minimala — bara tre konstanter och en villkorsändring i is_eeprom(). Koden vet nu att SRAM täcker $0000–$7FFF och att VIA bor på $A000. Allt annat är tri-state för fysiska kretsar.


// ==============================================================
// Steg 11 — städad adressrymd
// ==============================================================
// SRAM: $0000–$7FFF (32 KB, hela 62256-chippet)
// VIA:  $A000–$A00F (I/O-fönster)
// EEPROM: $8000–$FFFF (minus VIA-fönstret)
// Arduino: endast klocka + reset + diagnostik.

#include <Arduino.h>

#define PHI2     2
#define RESB     4
#define RWB      3
#define SYNC     13
#define BTN_CLK  11
#define BTN_INSTR 12

#define CLOCK_HZ 500
#define CLOCK_DELAY (1000 / (CLOCK_HZ * 2))

#define SRAM_END     0x7FFF   // NY — 32 KB nu
#define VIA_BASE     0xA000   // NY — flyttad från $4000
#define EEPROM_START 0x8000
#define EEPROM_END   0xFFFF

// --- is_sram() — hela nedre halvan, fysisk 62256 ---
bool is_sram(uint16_t addr) { return addr <= SRAM_END; }

// --- is_via() — I/O-fönster på $A000 ---
bool is_via(uint16_t addr) {
  return (addr >= VIA_BASE && addr < VIA_BASE + 16);
}

// --- is_eeprom() — övre halvan minus VIA-fönstret ---
bool is_eeprom(uint16_t addr) {
  if (is_via(addr)) return false;        // VIA stjäl 16 bytes
  return (addr >= EEPROM_START && addr <= EEPROM_END);
}

// --- read_mem() — Arduino svarar ENDAST utanför alla fysiska enheter ---
uint8_t read_mem(uint16_t addr) {
  if (is_sram(addr))   return 0;   // SRAM svarar
  if (is_via(addr))    return 0;   // VIA svarar
  if (is_eeprom(addr)) return 0;   // EEPROM svarar
  return 0xEA;
}

// --- write_mem() — bara utanför fysiska enheter ---
void write_mem(uint16_t addr, uint8_t val) {
  if (is_sram(addr))   return;
  if (is_via(addr))    return;
  if (is_eeprom(addr)) return;
}

// --- pulse() — en klockcykel, tri-state för SRAM/VIA/EEPROM ---
void pulse() {
  digitalWrite(PHI2, LOW);
  DDRA = 0x00;
  delay(CLOCK_DELAY);

  uint8_t kl = PINF;
  uint8_t kh = PINK;
  uint16_t a = (kl << 0) | (kh << 8);
  bool rw = digitalRead(RWB);

  if (rw && !is_sram(a) && !is_via(a) && !is_eeprom(a)) {
    DDRA = 0xFF;
    PORTA = read_mem(a);
  }

  digitalWrite(PHI2, HIGH);
  delay(CLOCK_DELAY);

  if (!rw && !is_sram(a) && !is_via(a) && !is_eeprom(a))
    write_mem(a, PINA);

  // Diagnostik
  Serial.print(rw ? "R" : "W");
  Serial.print(" $");
  Serial.print(a, HEX);
  if (is_sram(a))            Serial.print("  ← SRAM");
  else if (is_via(a))         Serial.print("  ← VIA");
  else if (is_eeprom(a))      Serial.print("  ← EEPROM");
  else if (a == 0xFFFC)      Serial.print("  ← RESET-VEKTOR LÅG");
  else if (a == 0xFFFD)      Serial.print("  ← RESET-VEKTOR HÖG");
  Serial.println();
}

// --- setup() — inget program att ladda, EEPROM levererar ---
void setup() {
  pinMode(RESB, OUTPUT); digitalWrite(RESB, LOW);
  pinMode(PHI2, OUTPUT); digitalWrite(PHI2, LOW);
  pinMode(SYNC, INPUT);
  pinMode(BTN_CLK,   INPUT_PULLUP);
  pinMode(BTN_INSTR, INPUT_PULLUP);
  pinMode(RWB, INPUT);
  Serial.begin(115200);
  DDRK = 0x00; DDRF = 0x00; DDRA = 0x00;

  Serial.println("Steg 11 — städad adressrymd");
  Serial.println("SRAM 32 KB ($0000-$7FFF), VIA ($A000), EEPROM ($8000+)");

  digitalWrite(RESB, LOW);
  for (int i = 0; i < 5; i++) pulse();
  digitalWrite(RESB, HIGH);

  Serial.println("CPU startad.");
}

// --- loop() — knappstyrning ---
void loop() {
  if (!digitalRead(BTN_CLK)) {
    delay(50); while (!digitalRead(BTN_CLK)); delay(50);
    pulse();
  }
  if (!digitalRead(BTN_INSTR)) {
    delay(50); while (!digitalRead(BTN_INSTR)); delay(50);
    do { pulse(); } while (!digitalRead(SYNC));
  }
  pulse();
}

Assembler-kod — program.cfg

Länkskriptet måste veta att $A000–$A00F är reserverat för VIA:n. Programmet placeras i ROM:en men hoppar över I/O-fönstret.

; program.cfg — steg 11
; Kod placeras i $8000–$9FFF och $A010–$FFFF,
; men hoppar över VIA-fönstret $A000–$A00F.

MEMORY {
    ZP:    start = $0000, size = $0100, type = rw;  ; zero page
    RAM:   start = $0200, size = $7E00, type = rw;  ; ledigt RAM
    ROM:   start = $8000, size = $2000, type = ro;  ; $8000–$9FFF
    ROM2:  start = $A010, size = $5FF0, type = ro;  ; $A010–$FFFF
}

SEGMENTS {
    ZEROPAGE: load = ZP,  type = zp;
    BSS:      load = RAM, type = bss;
    CODE:     load = ROM, type = ro;
    VECTORS:  load = ROM2, start = $FFFA, type = ro;
}

Programmet läggs i $8000–$9FFF (8 KB räcker gott). Reset-vektorn ligger i ROM2 på $FFFA–$FFFF — precis som alltid.

Lägg märke till skillnaden mot steg 10: SRAM-skrivningar kan nu ske var som helst i $0000–$7FFF, och VIA:n svarar på $A000. Bussloggen visar tydligt vilken enhet som pratar.

Om det inte fungerar

  • CPU:n läser $FFFC/$FFFD men hoppar till fel adress? EEPROM:ets /CE är förmodligen inte rätt avkodat. Kontrollera U5D — den måste vara LÅG när A15=1 OCH inte VIA.
  • VIA:n svarar inte på $A000? Kontrollera U5A–U5C-avkodningen. A15=1, A14=0, A13=1, A12=0 måste ge LÅG på /CS2. Dubbelkolla att RS0–RS3 fortfarande går till A0–A3.
  • SRAM fortfarande bara 16 KB? A14 (SRAM pin 1) är inte ansluten. Utan den kan processorn inte nå $4000–$7FFF.
  • Busskrockar? Två enheter kan svara samtidigt om avkodningen är fel. Mät /CE och /CS2 medan CPU:n läser — exakt en ska vara LÅG.
  • Programmet kraschar vid $A000? Länkskriptet placerade kod i VIA-fönstret. Kontrollera program.cfg — ROM-segmentet får inte inkludera $A000–$A00F.
