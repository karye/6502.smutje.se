Steg 7 — Riktigt RAM-chip

Mål

Koppla in ett fysiskt RAM-chip (62256 32 KB SRAM) och låt 6502:an läsa och skriva till det. Arduinon fortsätter emulera ROM i övre halvan av adressrymden ($8000–$FFFF) medan RAM-chippet hanterar den undre halvan ($0000–$7FFF). Vi verifierar att läsning och skrivning fungerar genom att modifiera räknarprogrammet från steg 6.

Adressrymdslayout

$FFFF ┌──────────────┐
      │  Arduino ROM  │  A15 = 1 → RAM /CE = HÖG (inaktivt)
$8000 ├──────────────┤
      │  62256 RAM   │  A15 = 0 → RAM /CE = LÅG (aktivt)
$0000 └──────────────┘

CPU:ns adresslinje A15 fungerar som chip select. När A15 = 0 ($0000–$7FFF) är RAM:et aktiverat och svarar. När A15 = 1 ($8000–$FFFF) är RAM:et avstängt och Arduinon tar över. Detta ger oss 32 KB RAM + 32 KB ROM-emulering — utan extra adressavkodningslogik.

Kopplingsschema

⚠ Busskollisionsrisk! RAM:et och Arduinon delar databuss med CPU:n. /OE måste vara HÖG under skrivning (hanteras av 74HC04-invertern). Arduinon måste sättas till INPUT när RAM:et driver bussen. Utan dessa skydd kortsluts utgångar och kretsar kan förstöras.

Arduino-kod — uppdaterad pulse()

Huvudändringen: Arduinon ska bara svara på adresser där A15 = 1 ($8000–$FFFF). Vid adresser med A15 = 0 lämnar vi databussen till RAM-chippet. pulse()-funktionen måste kontrollera adressens högsta bit innan den driver PORTA.

// -----------------------------------------------------------
// Steg 7 — RAM-chip vid $0000–$7FFF, Arduino ROM vid $8000–$FFFF
// -----------------------------------------------------------

void pulse() {
  // -- Fas 1: PHI2 låg — läs adress och RWB --
  digitalWrite(PHI2, LOW);
  delay(10);

  uint16_t a = (PINK << 0) | (PINF << 8);
  bool rw = digitalRead(RWB);
  bool arduino_ansvarar = (a & 0x8000);  // true om A15 = 1 ($8000–$FFFF)

  if (rw) {
    // --- LÄSCYKEL ---
    if (arduino_ansvarar) {
      // Arduino levererar data från sin minnesarray
      DDRA = 0xFF;
      PORTA = arduino_ansvarar ? read_mem(a) : 0x00;
    } else {
      // RAM-chippet driver databussen — Arduino håller sig undan
      DDRA = 0x00;
    }
    data = arduino_ansvarar ? read_mem(a) : PINA;
  } else {
    // --- SKRIVCYKEL ---
    // CPU:n driver databussen, Arduino läser passivt
    DDRA = 0x00;
  }

  // -- Fas 2: PHI2 hög --
  digitalWrite(PHI2, HIGH);
  delay(10);

  if (!rw) {
    uint8_t skriven_data = PINA;
    if (arduino_ansvarar) {
      // Spara även lokalt om adressen är i Arduino-området
      write_mem(a, skriven_data);
    }
    // RAM-chippet skriver automatiskt — /WE är kopplat till R/W
    data = skriven_data;
  }

  // LCD-utskrift som tidigare...
  lcd.setCursor(0, 0);
  lcd.print("A:"); lcd.print(a, HEX); lcd.print("    ");
  lcd.setCursor(0, 1);
  lcd.print("D:"); lcd.print(data, HEX); lcd.print("    ");

  Serial.print(rw ? "R" : "W");
  Serial.print(" $"); Serial.println(a, HEX);
}

Testning

  1. Koppla in 62256, 74HC04 och avkopplingskondensatorn
  2. Ladda upp den modifierade koden
  3. Stega med Knapp 2 (instruktionssteg) — följ programflödet i LCD:n
  4. Vid STX $0200: CPU:n skriver till RAM. Adress $0200 syns med W-prefix i serieövervakaren
  5. Vid LDA $0200: CPU:n läser tillbaka från RAM. LCD:n visar adress och det lästa värdet
  6. Verifiera att skrivet och läst värde är samma — RAM fungerar!
✅ Förväntat: CPU:n skriver till RAM och läser tillbaka korrekt värde. 62256:an svarar på $0000–$7FFF. Arduinon hanterar $8000–$FFFF. Första steget mot en dator med riktigt minne!

Hur fungerar det?

A15 som chip select: 6502:ans adressbuss har 16 linjer (64 KB adressrymd). Genom att koppla A15 direkt till RAM:ets /CE-pinne delar vi in minnet i två 32 KB-halvor — undre för RAM, övre för Arduino ROM. Inga extra avkodningskretsar behövs.

/OE via inverterare: RAM:ets /OE (output enable) måste vara LÅG vid läsning och HÖG vid skrivning. 6502:ans R/W-signal är HÖG vid läsning — alltså tvärtom. 74HC04 inverterar signalen så att /OE = LÅG när R/W = HÖG.

/WE direkt från R/W: /WE (write enable) är LÅG vid skrivning, och R/W är LÅG vid skrivning — de matchar! Därför kan /WE kopplas direkt till CPU:ns R/W utan inverering.

Busstristate: Under skrivcykler är både Arduinons PORTA och RAM:ets /OE i högimpedanstillstånd, så endast CPU:n driver databussen. Under läsning driver antingen RAM eller Arduino bussen — aldrig båda samtidigt.
